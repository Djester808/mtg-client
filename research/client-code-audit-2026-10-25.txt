Client code audit and fixes — 2026-10-25

Scope
Three parallel reviewers covered auth/community/forum/explore/commanders;
deck/collection/search/modal/AI; and game/SignalR/lobby/life-counter. The primary
reviewer checked store effects/reducers, session boundaries, knowledge lookup,
entry-point reachability, integration contracts and verification. This is a
repository-wide audit of those surfaces, not a claim that every possible defect
or architectural tradeoff has been eliminated.

Confirmed issues fixed
- Async state could cross entity, route or account boundaries. Mutation success
  actions now carry destination IDs; reducers reject stale destinations. Effects
  cancel active and queued work on session changes. Auth/profile callbacks and
  caches cannot restore the previous account. Root state resets at boundaries.
- Create/metadata writes were canceled or reordered by switchMap/mergeMap. They
  now serialize. Deck notes and secondary commanders survive optimistic updates.
- Detail route reuse retained editors, searches and AI state from another deck or
  collection. Those ID changes recreate the detail component. Public profile,
  forum, commanders and knowledge routes cancel/reset their own stale requests.
- Forum's bounded API exposed only the first page. Posts/comments now load more
  with offsets and deduplication. Copying preserves partner commanders and etched
  quantities/printings. The sibling API now includes the partner ID in its DTO.
- Search load-more, modal rulings, ownership, suggestions and AI streams could
  outlive their query, owner or component. Cancellation/reset guards now cover
  replacement and destruction, including cleanup of a late-created AI draft.
- Etched ownership, quantity reductions and price calculations were incomplete.
  Deck Other statistics double-subtracted cards with multiple types. Fixed both.
- Mana advice counted sideboards and repeated derived work; main-board analysis
  is memoized and its error/empty states recover. Forum filtering is memoized.
- SignalR reconnects and old callbacks could affect a newer table. Connections,
  callbacks and pending choices are scoped to their owning hub/game. Leaving the
  board disconnects, resets game/UI/selection state and cancels pending REST work.
- Lobby reads and life-counter dialogs could publish stale results. They cancel
  on replacement/close; recording an old game cannot mark a rematch recorded.
- Attachment lookup now builds one map instead of scanning the battlefield for
  each attachment. Startup keyword lookup has a bounded timeout; keyword sheets
  and knowledge searches survive failed requests without poisoning later queries.

Dead code / duplication
Removed the unreachable legacy CardComponent and its own tests/styles after
checking production imports and selector usage. Removed unused activateMana,
untapLand and setBlockerOrder client chains and the unused exported sortExplore.
Updated only the removed component's coverage/shared-treatment registrations.
Kept stateDiff and separate deck/collection domain reducers where callers or
semantics remain. Shared session cancellation and existing navigation helpers
replace repeated lifecycle/navigation logic. No cosmetic rewrite of large drag
or layout components and no claim of blanket SOLID compliance.
